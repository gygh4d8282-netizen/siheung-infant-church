# 운영 안내

## 1. 먼저 결정할 내용

- 정확한 대상 연령, 예배 요일·시간·장소, 첫 방문 안내
- 교회 공식 지도·문의 링크를 게시할지 여부
- 관리자로 초대할 교사 이메일과 계정 관리 담당자
- 서로 다른 두 공용 비밀번호와 안내 방법
- 교사가 검토한 첫 콘텐츠와 아동 개인정보가 없는 활동 사진
- Supabase·Vercel 계정 소유자, 도메인, 예산

서비스 가격과 무료 범위는 보장하지 않습니다. 생성·결제·배포는 서비스 화면에서 현재 조건을 확인한 뒤 진행하세요.

## 2. Supabase 준비

1. 운영자가 Supabase 프로젝트를 만듭니다.
2. SQL Editor에서 `supabase/migrations/001_initial.sql`, `002_file_cleanup.sql`을 순서대로 한 번씩 실행합니다. 기존 프로젝트의 같은 이름 테이블이나 버킷에 덮어써서 실행하지 마세요.
3. Database에서 RLS가 켜져 있는지, Storage의 네 버킷이 모두 private인지 확인합니다. `anon`/`authenticated`가 테이블이나 Storage를 직접 읽도록 정책을 추가하지 않습니다.
4. Authentication 설정에서 공개 신규 가입을 끕니다. 운영자가 교사 계정을 사전 등록하거나 초대합니다. 관리자 비밀번호는 12자 이상으로 설정합니다.
5. 관리자 계정의 User UID를 확인한 뒤 SQL Editor에서 아래처럼 등록합니다. 실제 이메일을 소스 코드에 넣지 않습니다.

```sql
insert into public.administrators(user_id, active)
values ('교사 계정의 실제 UUID', true);
```

모든 허가된 관리자에게 동일한 편집 권한이 있습니다. 계정 회수는 다음처럼 처리하고 Supabase Auth에서도 계정을 비활성화하거나 삭제합니다. 권한 검사는 매 요청마다 이루어집니다.

```sql
update public.administrators set active = false
where user_id = '회수할 계정의 실제 UUID';
```

## 3. 인증 이메일

Authentication URL Configuration의 Site URL에 실제 HTTPS 주소를 넣고 Redirect URL에 `https://실제도메인/auth/confirm`을 허용합니다. 로컬 테스트에는 `http://127.0.0.1:3000/auth/confirm`을 별도로 추가합니다.

이메일의 서버 확인 경로가 작동하도록 다음 템플릿 링크를 사용합니다. 서비스의 `{{ .TokenHash }}` 치환 구문을 그대로 둡니다.

- Reset Password: `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery`
- Invite User: `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=invite`

초대할 때에는 사용자가 링크를 누르기 전에 `administrators`에 해당 UID를 등록하세요. 링크가 만료되면 재설정 이메일을 다시 요청합니다. 실제 발송은 SMTP/이메일 발송 설정이 필요할 수 있으므로 메일 수신 테스트를 합니다.

## 4. 환경 변수와 배포

1. `.env.example`을 로컬에서 `.env.local`로 복사합니다.
2. Supabase URL과 공개 키, service_role 키를 해당 변수에 입력합니다.
3. `SESSION_SECRET`은 암호학적 무작위 32바이트 이상 값으로 설정합니다. Node.js에서 `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`로 생성할 수 있습니다. 결과는 환경 변수에만 보관합니다.
4. Vercel에 GitHub 저장소를 연결하고 Framework를 Next.js로 선택합니다. 환경 변수 5개를 설정하고 `APP_URL`에는 배포할 최종 HTTPS 주소를 넣습니다. 테스트용 미리보기 주소를 사용할 경우에도 해당 주소와 인증 리다이렉트를 맞춥니다.
5. `pnpm install --frozen-lockfile`, `pnpm test`, `pnpm build`를 확인한 뒤 배포합니다. 사용 중인 Next.js가 지원하는 Node 런타임(22 이상)을 선택합니다.
6. HTTPS에서 관리자 로그인·비밀번호 입력·파일 다운로드를 검증합니다. 운영 쿠키는 Secure를 사용하므로 HTTP 운영은 지원하지 않습니다. 로컬 HTTP 개발에서만 Secure 예외를 둡니다.

Vercel로 업로드 파일 전체를 보내지 않습니다. 관리자 인증 후 발급받은 업로드 토큰으로 Supabase private 임시 버킷에 전송하고, Vercel 서버가 검사 후 적절한 private 버킷에 저장합니다. 서비스별 저장공간·전송량·실행시간 설정은 실제 운영 환경에서 확인하세요.

## 5. 콘텐츠 관리

1. 하단의 **관리자 로그인**을 누릅니다.
2. 기본 안내를 입력합니다. 미확인 연락처나 주소를 임의로 넣지 않습니다.
3. 공용 비밀번호에서 교사 자료실과 사진첩의 비밀번호를 각각 설정합니다. 원문 조회 기능은 없습니다.
4. 해당 관리 메뉴에서 새 항목을 만들고 **초안 저장**합니다.
5. 필요한 파일을 올립니다. 사진은 대체 설명을 넣고 여러 장을 선택할 수 있습니다. 변환된 사진은 WebP로 저장되며 위치 등 EXIF가 제거됩니다. 사진마다 설명을 수정하고 대표 사진을 선택합니다.
6. 본문·첨부를 확인하고 검토 항목에 체크한 뒤 **검토 후 게시**합니다. 앨범에는 사진이 한 장 이상 있어야 합니다. 자료·사진 수정 후에도 다시 확인합니다.
7. **게시 취소하고 초안 저장**하면 이용자 화면에서 감춥니다. 이미 발급된 파일 링크는 최대 60초 후 만료되며 이미 내려받은 파일은 회수할 수 없습니다.

다른 교사가 먼저 저장하면 덮어쓰기를 거부합니다. **최신 목록 다시 보기**를 눌러 변경 내용을 확인한 뒤 다시 편집하세요. 파일을 바꾸기 전에 작성 중인 본문을 먼저 저장하세요.

일정은 시작·종료를 한국 시간으로 입력합니다. 종일 일정은 같은 날이면 시작 00:00, 종료 23:59로 입력합니다. 공개 범위는 반드시 선택합니다. 교사 일정은 공개 달력과 홈에 나타나지 않습니다.

일반 자료는 PDF/JPG/PNG/WEBP/HWP/HWPX/DOCX/PPTX/XLSX, 20MB 이하입니다. 사진첩은 JPG/PNG/WEBP, 10MB 이하입니다. 사진은 디코딩한 픽셀 수도 제한합니다. 확장자를 바꾼 실행파일, HTML, 매크로가 포함된 OOXML 문서는 거부합니다. 파일 검사는 백신 검사 또는 아동 개인정보/교리 자동 검토를 의미하지 않습니다.

## 6. 삭제·저장공간 정리

콘텐츠 삭제는 제목을 확인한 뒤 실행합니다. 해당 콘텐츠의 파일만 삭제 대상으로 등록하며 다른 콘텐츠의 파일에는 손대지 않습니다. 파일 삭제가 일시적으로 실패하면 `storage_deletions`에 남고 다음 관리자 저장 작업에서 재시도합니다. 미완료 임시 업로드는 생성 후 3시간이 지나면 다음 관리 작업에서 정리합니다. 운영자는 이 두 테이블을 주기적으로 확인하세요. 오래 방치된 실패는 Storage 연결과 할당량을 확인합니다. 삭제된 항목의 감사용 메타데이터는 DB에 남지만 사용자·관리자 목록에는 나오지 않습니다.

## 7. 비공개 공간 운영

- 자료실/사진첩 비밀번호는 다르게 전달합니다. 공용 비밀번호는 열람·다운로드만 허용합니다.
- 비밀번호 변경 즉시 해당 공간의 기존 세션이 무효화됩니다. 반대 공간에는 영향을 주지 않습니다.
- 브라우저의 **이 공간 잠그기**로 일반 열람 세션을 종료합니다. 관리자는 자신의 로그인 권한으로 비공개 공간을 볼 수 있으므로 완전히 나가려면 관리자 로그아웃도 합니다.
- 실패 횟수는 데이터베이스에 원문 입력 대신 HMAC 처리한 요청 출처 키로 기록합니다. Vercel에서는 신뢰하는 전달 헤더를 사용하며 15분에 공간별 5회로 제한합니다. 다른 프록시에 배포하려면 신뢰할 수 있는 출처 식별 방식을 별도로 조정하세요.
- DB/Storage 백업과 복구, 관리자 목록 점검은 운영 담당자의 업무입니다. 관리형 서비스의 백업 조건을 확인하세요.
