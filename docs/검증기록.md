# 검증 기록

## 로컬 검증

- 보안·PostgreSQL 테스트 16개 통과
- HTTP 검사: 공개/잠금/관리자 입장 화면 8개 정상 응답, 비로그인 관리/업로드 요청 차단, 요청 출처 위조 차단
- 브라우저 검사: 390px 휴대폰 메뉴·기본 일정 목록·달력 전환·월 이동, 1440px 유동형 홈, 두 폭에서 가로 넘침 없음
- Next.js 프로덕션 빌드와 TypeScript 검사
- scrypt 해시·오입력, HMAC 세션의 변조/공간 분리/버전 변경/12시간 만료
- 성경·교리 자료 검토 필수, 날짜와 공개 범위 검증
- 파일 제한과 실제 형식 검사, 매크로 포함 문서 거부
- 사진 EXIF 제거와 썸네일 생성
- PGlite PostgreSQL에서 실제 마이그레이션 적용, 관리자 2명 공동 편집, 동시 수정 거부, 미허가 계정 차단
- DB 차원의 검토/앨범 사진/공개 범위 제약, 공간별 비밀번호 버전, 요청 횟수 제한
- anon/authenticated 역할의 직접 DB 조회와 관리 함수 실행 거부
- 파일 추가 후 초안 전환, 삭제할 콘텐츠의 파일만 정리 대상으로 등록

테스트 데이터는 메모리 안의 독립 DB에만 생성되며 실제 웹사이트에 게시하지 않습니다.

## 연결 후 필수 확인

실제 Supabase 프로젝트, SMTP, 운영 HTTPS 도메인이 아직 연결되지 않았으므로 다음 통합 검증은 운영 설정 후 수행해야 합니다.

1. 허가한 관리자 2명이 실제 로그인·로그아웃·초대/재설정 메일을 이용할 수 있는지
2. 두 공용 비밀번호의 독립성, 12시간 만료, 변경 후 기존 쿠키 거부
3. 비공개 페이지/파일 주소에 비로그인, 반대 공간 세션, 일반 공용 세션으로 접근하는 권한 행렬
4. 초안/삭제/교사 일정이 공개 홈·응답·달력에 나타나지 않는지
5. 두 관리자가 같은 버전을 저장했을 때 한쪽이 409 충돌을 받는지
6. 실제 20MB 자료, 10MB 사진의 직접 전송과 검증, 파일 변경 시 재검토와 초안 전환
7. 이미지 원본/썸네일이 public Storage URL로 열리지 않는지, 60초 서명 URL이 만료되는지
8. 변경된 파일·앨범의 검토 확인 누락이 거부되는지
9. 삭제 후 다른 콘텐츠 파일이 유지되는지, 일시적 Storage 삭제 실패가 다음 관리 작업에서 정리되는지
10. 작은 휴대폰과 PC에서 목록·달력, 자료 필터, 사진 확대, 키보드 탐색이 작동하는지

이 목록은 미검증 항목을 숨기지 않기 위한 운영 확인표이며, 서비스를 연결하지 않은 상태에서 전체 인수 검증이 끝났다고 주장하지 않습니다.
